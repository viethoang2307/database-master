# SQL Server to PostgreSQL Dialect Guide

The source course teaches Microsoft SQL Server and T-SQL. This repository uses PostgreSQL as the executable dialect. Equivalent concepts are compared explicitly so that the learner understands what is portable SQL and what is vendor-specific.

| SQL Server / T-SQL | PostgreSQL | Engineering note |
| --- | --- | --- |
| `TOP (10)` | `LIMIT 10` or `FETCH FIRST 10 ROWS ONLY` | Always pair top-N queries with a deterministic `ORDER BY`. |
| `ISNULL(value, fallback)` | `COALESCE(value, fallback)` | `COALESCE` is standard SQL and accepts more than two arguments. Do not repeat claims that one is universally faster. |
| `GETDATE()` | `CURRENT_TIMESTAMP` / `now()` | `CURRENT_TIMESTAMP` is transaction-stable; `clock_timestamp()` changes during a transaction. |
| `IDENTITY` | `GENERATED BY DEFAULT AS IDENTITY` | Prefer identity columns over legacy serial syntax for new PostgreSQL schemas. |
| `NVARCHAR` | `text` or `varchar` | PostgreSQL strings are Unicode under the database encoding. Use length limits only when they express a business rule. |
| `BIT` | `boolean` | PostgreSQL uses `TRUE` and `FALSE`. |
| `DATEPART` | `EXTRACT` / `date_part` | Return type and formatting differ; examples show explicit casts when needed. |
| `DATEDIFF` | timestamp/date subtraction or interval arithmetic | There is no single drop-in function with identical semantics for every unit. |
| `DATEADD` | `timestamp + interval` | Use typed intervals such as `INTERVAL '7 days'`. |
| `FORMAT` / `CONVERT` for display | `to_char` | Keep formatting at presentation boundaries when possible. |
| `#temp_table` | `CREATE TEMP TABLE` | Temporary tables are session-scoped in PostgreSQL. |
| `CREATE OR ALTER PROCEDURE` | `CREATE OR REPLACE PROCEDURE` | PostgreSQL procedures and functions have different invocation and transaction semantics. |
| `TRY...CATCH` | PL/pgSQL `EXCEPTION` block | An exception rolls back the current PL/pgSQL block's database changes. |
| clustered index | no identical table-clustering model | PostgreSQL heap tables and indexes have different physical behavior; `CLUSTER` is a table rewrite operation, not a permanent clustered index. |
| columnstore index | no built-in identical feature | Teach row-oriented PostgreSQL indexes, BRIN, materialized views and warehouse design instead of pretending the features are equivalent. |

## Correction policy

Statements from the transcript are treated as hypotheses until verified against PostgreSQL documentation or a reproducible lab. Vendor-specific behavior is labeled. Performance conclusions are not presented as universal rules because planner decisions depend on data distribution, statistics, cost settings and hardware.
